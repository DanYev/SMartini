# Tests

## Layout

- `refs/<MOL>/` — regression inputs and expected outputs:
  - `<MOL>_initial.itp` — reference CG topology generated by `1_gen_cg_topo.py`
  - `<MOL>.sdf` — optional all-atom input molecule; if absent, `config.yml`
    must contain `smiles:` and the pipeline generates the SDF during the test
  - `config.yml` — per-molecule settings used to generate the reference
- `refs/logP_smi_test.dat` — frozen logP lookup table used by the tests. It is
  the bundled `smartini/logP_smi_extended.dat` plus two fragments that are not
  in the bundled table (`cC=C` for FTA and `OC=O` for HEM). Without those
  entries the pipeline queries vcclab.org, which currently returns an error and
  makes bead-type assignment depend on network/RDKit fallback behaviour. The
  frozen values reproduce the committed reference types.
- `output/<MOL>/` — artifacts generated while running the tests. This directory
  is recreated for every molecule at the start of a test session and is
  git-ignored, but the files are kept on disk for inspection after a run.
- `itp_utils.py` — ITP section splitter and molecule discovery.
- `conftest.py` — session fixture that runs the pipeline once per molecule.
- `test_gen_cg_topo.py` — per-section regression comparisons.

## Running

Use the `smartini` environment:

```bash
/home/dyangali/.conda/envs/smartini/bin/python -m pytest tests -v
```

Run a single molecule or section with `-k`:

```bash
/home/dyangali/.conda/envs/smartini/bin/python -m pytest tests -k "CLA-atoms"
```

## How comparison works

The reference and generated ITP files are split into the header plus one block
per `[ section ]` directive (moleculetype, atoms, bonds, constraints, angles,
dihedrals, exclusions, position_restraints, ...). Each block is compared
exactly and separately, so a failure names the molecule and the specific
section that changed.
